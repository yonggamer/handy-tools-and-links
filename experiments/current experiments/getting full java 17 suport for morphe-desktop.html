Getting Full Java 17 Support for Morphe Desktop

Investigating and improving Java 17 compatibility for Morphe Desktop, with a focus on getting both the graphical interface and command-line interface working across different Java architectures.

⚠ Partially supported

📖 About this experiment

This experiment investigates the current Java 17 compatibility of Morphe Desktop.

The main objective is to achieve full Java 17 compatibility for both 64-bit and 32-bit Java Runtime Environments (JREs).

At the moment, Java 17 support is only partial overall. The 64-bit JRE already works with both the graphical user interface (GUI) and the command-line interface (CLI), while the 32-bit JRE currently only works with the CLI.

🎯 Goals

  • Achieve full Java 17 compatibility.
  • Get the graphical interface working with 32-bit Java 17.
  • Maintain 64-bit Java 17 GUI and CLI support.
  • Investigate architecture detection and dependency compatibility.
  • Verify native libraries and bootstrap downloads.
  • Test the application on different Java runtimes.

🔍 Technical investigation

These four files in the Morphe Desktop repository are the main files to investigate for changes related to Java 17 and architecture compatibility.

GenerateBootstrapConstantsTask.java Bootstrap constants and native library hashes ↗ libs.versions.toml Dependency versions and Compose Desktop libraries ↗ PlatformDetector.kt Operating system and architecture detection ↗ BootstrapDownloaderVerificationTest.kt Bootstrap verification and native library tests ↗

💻 Findings from the current source code

1. PlatformDetector.kt

The current platform detector recognizes x64 and ARM64 architectures. It does not explicitly recognize x86/32-bit architecture.

2. GenerateBootstrapConstantsTask.java

The bootstrap generation task creates SHA-256 hashes for native dependencies and Skiko runtime artifacts for six platform targets: macOS x64, macOS ARM64, Linux x64, Linux ARM64, Windows x64 and Windows ARM64.

3. libs.versions.toml

This file defines dependency versions, including Compose Desktop and other libraries. It is worth checking whether the selected dependency versions and available native artifacts meet the desired Java 17 compatibility requirements.

4. BootstrapDownloaderVerificationTest.kt

The existing tests verify that bootstrap constants are generated, hashes have the expected format, and Skiko/Skia classes can be loaded. They also check OSHI initialization.

These tests do not currently establish that the 32-bit graphical interface works. Additional architecture-specific testing would be needed.
